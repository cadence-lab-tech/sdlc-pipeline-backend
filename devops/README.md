# devops

Инфраструктура sdlc-pipeline в Timeweb Cloud и инструменты для работы с ней.
Продолжение [deploy/README.md](../deploy/README.md): там — что и куда
разворачивается, здесь — чем это создаётся и чем чинится.

Рассчитано на то, что рядом работает агент. Отсюда главное свойство папки:
**читающие команды и меняющие разведены по разным скриптам**, и граница
между ними проверяется кодом, а не соблюдается на честном слове. Правила
для агента — в [CLAUDE.md](CLAUDE.md), они подхватываются автоматически.

```
devops/
  CLAUDE.md            правила работы с продом (агент читает их сам)
  cloud-init.yaml      первичная настройка машины
  .env.example         токен Timeweb и параметры подключения
  terraform/           проект, сервер, IPv4, файрвол, A-запись, бакет
  bin/
    tf.sh              terraform с токеном и из нужного каталога
    twc-get.sh         читающий запрос к API Timeweb (только GET)
    bootstrap-env.sh   собрать /opt/sdlc/.env на машине — один раз
    remote-read.sh     читающие команды — белый список внутри
    remote-run.sh      меняющие команды — спрашивают подтверждение
    diagnose.sh        один срез машины, с него начинается разбор аварии
```

## Установка

```bash
brew install hashicorp/tap/terraform   # в homebrew-core формулы нет
cp devops/.env.example devops/.env     # TWC_TOKEN и адрес машины
```

Токен — в [панели Timeweb](https://timeweb.cloud/my/api-keys). **Отключите
у него подтверждение удаления серверов через Telegram** — иначе Terraform
будет виснуть, ожидая нажатия в мессенджере.

## Создание инфраструктуры

```bash
ssh-keygen -t ed25519 -C sdlc-deploy -N '' -f ~/.ssh/sdlc-deploy
cp devops/terraform/terraform.tfvars.example devops/terraform/terraform.tfvars
$EDITOR devops/terraform/terraform.tfvars    # ключ, домен, тариф

./devops/bin/tf.sh init
./devops/bin/tf.sh plan
./devops/bin/tf.sh apply
```

Что появится: SSH-ключ, плавающий публичный IPv4,
машина Ubuntu 24.04 с `cloud-init` (Docker, пользователь `deploy`, ufw,
ротация логов, cron дампа), группа файрвола с открытыми 22/80/443, A-запись
домена и приватный бакет под содержимое артефактов.

**IPv4 — отдельный ресурс.** У `twc_server` нет аргумента «дай публичный
IPv4»: машина поднимается только с IPv6, а четвёртая версия приезжает
`twc_floating_ip`. Плавающий выбран сознательно — он переживает пересоздание
машины, и A-запись с `SSH_KNOWN_HOSTS` при переезде не меняются.

**Всё в общем проекте аккаунта.** Отдельный проект в панели Terraform не
заводит: у файрвола и плавающего IP нет `project_id`, и половина ресурсов всё
равно осталась бы в общем. Перенос сервера и бакета в свой проект — руками в
панели, на state это не влияет.

**Технического домена не будет.** Панель выдаёт серверу `<id>-<логин>.twc1.net`,
API — нет. Поэтому адрес — своя зона: с `manage_dns = true` запись ставит
Terraform, на чужих NS — руками у регистратора.

**S3 живёт только в `ru-1`.** Все пресеты хранилища привязаны к нему; при
переезде сервера в другую зону бакет остаётся на месте. Пресет за 1 ₽ —
промо, один на аккаунт; берётся Standard 10GB (`s3_preset_id`).

Дальше:

```bash
./devops/bin/tf.sh output server_ip          # → SDLC_SSH_HOST и секрет SSH_HOST
ssh-keyscan <ip>                             # → секрет SSH_KNOWN_HOSTS
ACME_EMAIL=you@example.ru ./devops/bin/bootstrap-env.sh   # /opt/sdlc/.env
```

`bootstrap-env.sh` подставляет домен и ключи S3 из state и генерирует
пароль базы, токен администратора и секрет вебхука **на самой машине** —
на ноутбуке значения не появляются. Terraform их не знает и не должен:
попав в конфиг, они попадут и в state в открытом виде. Дальше — секреты в
GitHub и первая выкладка, см. [deploy/README.md](../deploy/README.md).

### Состояние

State лежит локально, в `devops/terraform/terraform.tfstate`, и **в git
не едет** — там ключи S3 и отпечатки. Пока инфраструктурой управляет один
человек с одной машины, этого достаточно. Как только их станет двое, state
надо унести в общий бакет: `terraform` умеет S3-бэкенд, а бакет Timeweb
совместим с ним при `skip_credentials_validation`, `skip_region_validation`
и явном `endpoints.s3`. Отдельный бакет под state, не тот, где артефакты.

Файл `.terraform.lock.hcl`, наоборот, коммитится — он пинует версию и хеши
провайдера.

## Разбор аварии

```bash
./devops/bin/diagnose.sh
```

Один читающий срез: выложенные теги, состояние контейнеров, живость каждого
сервиса изнутри машины, ошибки в логах, диск, память, сроки сертификатов,
бэкапы и коды ответа снаружи. Ничего не меняет. С него начинается любой
разбор — в том числе потому, что он отделяет «лежит сервис» от «лежит
прокси» до того, как кто-то начнёт чинить не то.

Дальше — точечно:

```bash
./devops/bin/remote-read.sh logs worker 300
./devops/bin/remote-read.sh errors
./devops/bin/remote-read.sh health
./devops/bin/remote-read.sh version
./devops/bin/remote-read.sh env-keys      # ИМЕНА переменных, без значений
./devops/bin/twc-get.sh servers           # что видит облако
```

Всё, чего в этом списке нет, идёт через `remote-run.sh` и требует
подтверждения:

```bash
./devops/bin/remote-run.sh 'docker compose restart worker'
./devops/bin/remote-run.sh './deploy.sh backend a1b2c3d'
```

## Типовые аварии

**Машина не отвечает ни на одном порту.** Плавающий IP выделен, но не
прописан в сети — Timeweb делает это асинхронно и иногда не делает. Признак:
таймаут даже там, где ничего не слушает (должен быть RST). Лечится
перепривязкой: `tf.sh apply -var attach_floating_ip=false && tf.sh apply`.

**Сертификата нет.** `remote-read.sh logs caddy 100` — Let's Encrypt
отвечает, почему: чаще всего A-запись ещё не разъехалась (`dig +short
<домен>`) или закрыт 80-й порт. Caddy повторяет попытки сам, чинить его не
надо — чинить DNS.

**После выкладки api не поднимается.** `remote-read.sh logs api 100`: на
старте он катит миграции и валидирует окружение, и обе причины видны в
первых строках. Откат — `remote-run.sh './deploy.sh backend $(cat
.last-ok-backend)'`; миграции при этом назад не катятся, поэтому откат
работает, только если новая миграция была совместима со старым кодом
(конвенция миграций в `CLAUDE.md` репозитория этого требует).

**Выкладка руками не может скачать образ.** Пакеты в GHCR приватные;
workflow логинится токеном прогона, который живёт до его конца. Для ручной
выкладки — `docker login ghcr.io` на машине с personal access token
`read:packages`, либо запустить workflow: `gh workflow run deploy.yml -f
tag=<sha>`.

## Границы

Что здесь **не** описано и остаётся ручной работой: секреты и переменные в
GitHub, OAuth-учётные данные GitHub App, ключ Voyage, домен у стороннего
регистратора (при `manage_dns = false`).

Чего в конфигурации намеренно нет — и что делать, когда понадобится:

- **Управляемой базы.** Postgres в контейнере на той же машине. DBaaS Timeweb
  умеет pgvector (расширение включается в панели), переезд — это
  `twc_database_cluster` здесь, минус сервис `postgres` в compose и внешний
  `SDLC_DATABASE_URL` в `.env`. Первое, что стоит сделать, когда потеря
  машины перестанет быть приемлемой.
- **Второй машины.** Реплики api уже умеют жить без общего тома (решение
  0028, содержимое в S3), но балансировщик и вторая машина — отдельный шаг.
- **App Platform Timeweb.** Отвергнут, причины в решении 0031: нет ресурса в
  Terraform, образы только из Docker Hub и только публичные, compose без
  томов, воркер без порта не описан.
